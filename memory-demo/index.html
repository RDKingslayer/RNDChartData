Watching memory in DevTools

    
    
        
  1. Memory tab: the "Select JavaScript VM instance" list shows the page and each worker
            (producer-worker.js, consumer-worker.js) separately. Pick a worker, choose
            "Allocations on timeline", start recording, press Run, stop recording after the run.
    2. 
        
  2. ArrayBuffer contents live outside the JS heap. In a heap snapshot they appear as
            system / JSArrayBufferData under each ArrayBuffer, and they are not part of
            performance.memory. The buffers line counts them per worker and works on any page;
            "Measure all threads" gives the browser's own total but, like SharedArrayBuffer, needs cross-origin isolation.
            Chrome's Task Manager (Shift+Esc) also shows the whole tab.
    3. 
        
  3. Performance tab with the "Memory" checkbox shows the heap over time with GC drops, which is the easiest
            way to see a spike and whether it comes back down.
    4. 
        
  4. Compare a 1-second burst in each mode. Take a heap snapshot (or measure) before the run and a few seconds
            after it. Memory should return to the baseline in every mode except "Simulate a leak"; starting a new run clears that.
